# LLM Analytics MCP

## 1. Обзор проекта

LLM Analytics MCP — локальный сервер Model Context Protocol для
детерминированного анализа CSV- и XLSX-файлов. Через него Claude Desktop может
загрузить набор данных, изучить и очистить его, точно рассчитать агрегации и
корреляции, построить PNG-графики, а затем превратить структурированные
результаты в понятный отчет.

Проект намеренно остается небольшим. В нем нет собственного chat UI, базы
данных, облачного сервиса, клиента LLM API и требований к API key.

## 2. Какую проблему решает проект

LLM хорошо понимает запрос пользователя и объясняет результаты, но не должен
оценивать суммы по сырым строкам или считывать точные значения с изображения
графика. Этот сервер предоставляет MCP-совместимой LLM детерминированные Python
tools для вычислений, статистики, очистки и визуализации. Основной принцип:
**Python считает, LLM объясняет.**

## 3. Архитектура

```text
Claude Desktop / LLM
        |
        | MCP tool calls через stdio
        v
MCP Server (src.server)
        |
        v
Tool adapters
        |
        v
Skills / domain logic
        |
        +--> DatasetRegistry
        +--> pandas
        +--> matplotlib
```

Сервер связывает `DataTools`, `AnalysisTools` и `VisualizationTools` с одним
общим `DatasetRegistry`, хранящимся в памяти. `load_data` сохраняет DataFrame и возвращает
непрозрачный `dataset_id`; последующие вызовы используют этот идентификатор.
DataFrame никогда не пересекает границу MCP.

Подробное обоснование решений и точки расширения описаны в
[ARCHITECTURE.md](ARCHITECTURE.md).

## 4. Технологический стек

- Python 3.12.6 — проверенная конфигурация; код рассчитан на Python 3.11+
- официальный Python MCP SDK с транспортом stdio
- pandas для табличных данных и детерминированных вычислений
- matplotlib для создания PNG без графического интерфейса
- Pydantic для строгих JSON-совместимых контрактов результатов
- openpyxl для загрузки XLSX
- pytest для unit-, integration-, MCP- и demo-тестов

## 6. Установка

Клонируйте или распакуйте репозиторий и откройте PowerShell в его корне:

```powershell
cd C:\path\to\llm-analytics-mcp
```

Проект проверен на Python 3.12.6. Также должен подойти Python 3.11 или новее.

## 7. Настройка виртуального окружения Python

Создайте и активируйте локальное виртуальное окружение:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
```

Последняя команда должна показать Python 3.12.x. Если PowerShell блокирует
скрипт активации, используйте терминал с разрешенным выполнением локальных
скриптов или напрямую вызывайте `.venv\Scripts\python.exe` в командах ниже.

## 8. Установка зависимостей

При активном виртуальном окружении выполните:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Проекту не нужны LLM SDK, Claude API key, LangChain или LangGraph.

## 9. Запуск тестов

Запускайте набор тестов через активный интерпретатор:

```powershell
python -m pytest
```

Вызов `python -m pytest` гарантирует, что корень проекта разрешается тем же
интерпретатором, которому принадлежат установленные зависимости.

## 10. Генерация тестовых данных

Чтобы создать детерминированный набор продаж за 2023–2024 годы, выполните:

```powershell
python scripts/generate_sample_data.py
```

Скрипт перезаписывает `data/sales_data.csv`, используя фиксированный seed.
Получается 195 строк с реалистичными различиями между продуктами и регионами,
контролируемым шумом, тремя точными дубликатами, четырьмя пропущенными
числовыми значениями и намеренно добавленными выбросами Sales/Profit.

## 11. Запуск детерминированного demo

```powershell
python demo/run_demo.py
```

Демонстрационный скрипт использует реальные классы слоя tools и один общий `DatasetRegistry`. Он
загружает, профилирует, очищает, агрегирует и визуализирует тестовый набор.
Это проверка серверной части, **а не клиент LLM**; скрипт не генерирует бизнес-
рекомендации.

При повторном запуске заменяются только стабильные артефакты
`output/demo_*.png`, принадлежащие этому demo.

## 12. Ручной запуск MCP Server

Из корня репозитория при активном виртуальном окружении выполните:

```powershell
python -m src.server
```

Процесс ожидает MCP-сообщения в stdin и записывает сообщения протокола в stdout,
поэтому отсутствие обычного вывода в терминале ожидаемо. Для остановки нажмите
`Ctrl+C`. Журналы приложения должны направляться в stderr, поскольку stdout
зарезервирован для трафика MCP stdio.

## 13. Настройка Claude Desktop

В обычной Windows-установке конфигурация MCP для Claude Desktop обычно
находится по адресу:

```text
%APPDATA%\Claude\claude_desktop_config.json
```

Этот путь и необходимость полного перезапуска подтверждены в
[официальном руководстве Python MCP SDK](https://py.sdk.modelcontextprotocol.io/get-started/real-host/).
Если директории еще нет, сначала один раз запустите Claude Desktop.

Используйте [claude_desktop_config.example.json](claude_desktop_config.example.json)
как шаблон структуры:

```json
{
  "mcpServers": {
    "analytics": {
      "command": "PATH_TO_PROJECT_PYTHON",
      "args": ["-m", "src.server"],
      "cwd": "PATH_TO_PROJECT",
      "env": {
        "PYTHONPATH": "PATH_TO_PROJECT"
      }
    }
  }
}
```

Замените оба шаблонных значения абсолютными путями:

- `PATH_TO_PROJECT_PYTHON` — путь к `python.exe` виртуального окружения.
- `PATH_TO_PROJECT` — корень репозитория; он используется как `cwd` и как
  явный `PYTHONPATH`.

Для копии репозитория в каталоге, использованном при разработке проекта, значения
концептуально выглядят так:

```text
C:\PythonProjects\llm-analytics-mcp\.venv\Scripts\python.exe
C:\PythonProjects\llm-analytics-mcp
```

В JSON обратные слеши Windows необходимо удваивать. Если конфигурация уже
содержит другие серверы, добавьте `analytics` в существующий объект
`mcpServers`, не заменяя весь файл.

Установка Claude Desktop из Microsoft Store/MSIX может читать конфигурацию не
из обычного `%APPDATA%\Claude`, а из виртуализированного каталога приложения в
`LocalAppData\Packages`. Не подставляйте в документацию или общий шаблон имя
пользователя либо идентификатор MSIX-пакета. Чтобы надежно открыть файл,
который использует именно установленная версия Claude Desktop, выберите
`Settings -> Developer -> Edit config`.

Если MCP process запускается, но завершается с ошибкой
`ModuleNotFoundError: No module named 'src'`, Claude Desktop не видит корень
репозитория в Python import path. Явное значение
`"PYTHONPATH": "PATH_TO_PROJECT"` в секции `env` исправляет эту ситуацию.

После сохранения полностью завершите Claude Desktop, включая фоновый процесс,
и откройте приложение снова. В разделе tools/integrations убедитесь,
что сервер `analytics` подключен и видны все восемь tools из следующего
раздела. Если запуск не удался, проверьте `%APPDATA%\Claude\logs` и убедитесь,
что оба настроенных пути существуют.

Интеграция реально проверена в Windows с Claude Desktop: сервер отображался как
`Running`, а Claude успешно выполнил полный workflow через все восемь tools:
`load_data`, `describe_data`, `clean_data`, `aggregate_data`, `plot_trend`,
`plot_bar`, `plot_distribution` и `correlation_analysis`.

## 14. Доступные MCP tools

| Tool | Назначение и основные параметры | Результат | Когда LLM следует использовать |
|---|---|---|---|
| `load_data` | Загружает CSV или XLSX из `file_path` и регистрирует набор. | `DatasetInfo` с `dataset_id` и сведениями о схеме | Первый вызов для нового файла. |
| `describe_data` | Профилирует `dataset_id`: типы, пропуски, дубликаты, статистику, категории и диапазоны дат. | `DataProfile` | Сразу после загрузки и до выбора анализа. |
| `clean_data` | Опционально обрабатывает пропуски, удаляет точные дубликаты и обнаруживает IQR-выбросы. | `CleaningReport` | После того как профилирование выявило проблемы качества. |
| `aggregate_data` | Группирует по `group_by`, вычисляет `metric` через `sum`, `mean`, `median`, `min`, `max` или `count`, сортирует и ограничивает результат. | `AggregationResult` | Для точных сравнений регионов, продуктов и других измерений. |
| `plot_trend` | Строит числовой `y_column` по временному `x_column`, при необходимости с частотой `D`, `W`, `M`, `Q` или `Y`. | `ChartResult` с путем к PNG, сводкой и нанесенными значениями | Для временных рядов. |
| `plot_distribution` | Строит гистограмму для числового `column` с настраиваемым `bins`. | `ChartResult` с путем к PNG, статистикой и количеством значений по интервалам | Для изучения разброса, асимметрии и крайних значений. |
| `plot_bar` | Агрегирует `value_column` по `category_column` с параметрами `aggregation` и `top_n`. | `ChartResult` с путем к PNG и точными сгруппированными значениями | Для визуального сравнения продуктов, регионов и категорий. |
| `correlation_analysis` | Вычисляет корреляции Pearson для числовых столбцов и строит тепловую карту. | `CorrelationResult` с матрицей, сильнейшими парами и путем к PNG | Для изучения линейных связей после знакомства с набором; корреляция не означает причинность. |

Все результаты JSON-совместимы. Visualization tools возвращают точные
использованные значения вместе с путем к PNG, поэтому LLM не приходится
оценивать числа по изображениям.

## 15. Пример запроса для Claude

Готовая версия находится в [demo/claude_prompt.txt](demo/claude_prompt.txt):

```text
Проанализируй ./data/sales_data.csv.

Сначала изучи набор данных и при необходимости устрани проблемы качества.

Затем:
- определи основные закономерности продаж и прибыли;
- рассчитай точные сравнения с помощью аналитических tools;
- создай не менее трех полезных визуализаций;
- включи динамику продаж во времени;
- сравни важное категориальное измерение;
- выполни correlation analysis.

Основывай каждое числовое утверждение на результатах tools, а не на оценке
значений по изображениям графиков.

В конце предоставь:
1. краткое резюме качества данных;
2. ключевые выводы;
3. практические бизнес-рекомендации.
```

## 16. Ожидаемый порядок работы

Ожидаемая последовательность верхнего уровня:

```text
load_data
-> describe_data
-> clean_data
-> aggregate_data
-> visualizations
-> correlation_analysis
-> финальный текст LLM
```

Это не жестко заданный конвейер. Claude может выбрать другой корректный
порядок, пропустить ненужные операции или выполнить дополнительные агрегации
с учетом профиля и запроса пользователя. Каждый вызов после загрузки должен
использовать возвращенный `dataset_id`. Идентификаторы и связанные с ними
DataFrame существуют только в течение жизни процесса сервера.

## 18. Известные ограничения

- Наборы данных хранятся в памяти и исчезают после остановки сервера.
- Для загрузки используются локальные пути, доступные процессу сервера.
- Это однопроцессный прототип без аутентификации.
- Нет изоляции пользователей или сессий.
- Очистка использует простые детерминированные правила median, mode,
  duplicate и IQR.
- Для отчетов и произвольных файлов графиков нет постоянного жизненного цикла хранения.
- Для больших наборов нет фоновых задач или очереди.
- Файлы графиков локальны и должны быть доступны на машине клиента.
- Качество финального текста зависит от подключенного MCP-совместимого LLM
  клиента.

- Асинхронная или фоновая обработка больших наборов
